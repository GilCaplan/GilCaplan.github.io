Cost predictors — the real trained models, in your browser

These run the project's actual trained XGBoost models live client-side — no server, no API key. Each model's complete tree structure was exported from its Python pickle using XGBoost's native model JSON (Booster.save_model) — which keeps every split_index, split_condition, default_left and leaf weight — then evaluated by a tiny vanilla-JS tree walker. All three predictors below reproduce the original Python/XGBoost output to within ~10⁻³ or better on held-out inputs. These are the exact committed weights, not a retrain.

1 · Lodging cost predictor

What it is: lodging_cost_predictor_v1.pkl — an XGBoost regressor (reg:squarederror) trained on the project's Airbnb listings. Output is price per night; total = per-night × nights (with the agent's per-guest floor). How to use: pick a region + room type and set the listing attributes. Parity vs Python: ~6×10⁻⁵.

Features: guests, listing rating, review count, amenities count, host score, description length, one-hot room_type (baseline = Entire Home/Apt), one-hot state/region. The dataset is global Airbnb data, so the region list includes some non-US regions the model also learned.

Honest note: these are the real exported weights, not a retrain — the JS tree evaluator reproduces the committed XGBoost model's raw output. Dataset RMSE was about $143 with a mean nightly price near $185, so treat single predictions as ballpark.

2 · Food cost predictor

What it is: food_cost_predictor_v1.pkl — an XGBoost regressor (300 trees) that predicts a restaurant meal price from state + cuisine + vibe rating. The food agent then combines that meal price with the USDA food-plan grocery costs (scaled by a per-state grocery index) and your eating-out ratio to produce a total food cost for the trip. How to use: set who's traveling, the cuisine/quality, and how much you'll eat out vs. cook. Parity vs Python (full pipeline): exact (0.0).

Model features: rating (vibe), review_count (fixed at 150 like the agent), one-hot state, one-hot cuisine. Grocery side uses real USDA low/moderate/liberal plans × demographics × the dataset's state grocery index.

3 · Entertainment cost predictor

What it is: entertainment_cost_model.pkl — an XGBoost regressor (100 trees, R²≈0.987) that predicts total entertainment spend for the trip from a city's real venue profile plus party size, days, and travel style. How to use: pick a city (its real venue stats from city_profiles.csv feed the model) — if the exact city isn't in the dataset the agent falls back to a state average, then a national average, exactly as in the Python code. Parity vs Python (full pipeline incl. fallbacks): ~5×10⁻³.

Features: venue_count, avg_price, price_std, avg_rating, avg_popularity, category mix (pct_museum/theme_park/outdoor/tour/attraction), audience mix, pct_accessible, pct_kid_friendly, plus num_people, num_days and a budget→travel-style encoding.

Venue recommender — the real cosine-similarity engine, in your browser

This runs the project's actual recommendation engine (recommendation_engine.pkl, from sub_agents/recommendation_entertainment_agent.py) live client-side — no server, no API key. It's a content-based cosine-similarity recommender over 2,425 real venues in 623 US/CA cities. Every venue is a 20-dimensional feature vector; your preferences become a vector too; the engine L2-normalizes both and ranks venues by cosine similarity (a normalized dot product), breaking ties by popularity_score — exactly as the Python agent does.

Features (20): 7 one-hot categories (museum, tour, sports_recreation, performing_arts, attraction, outdoor_activity, theme_park), 4 one-hot price tiers (budget/medium/expensive/luxury), 3 one-hot audiences (family/adults/all), plus normalized popularity, rating, duration and flags is_kid_friendly, is_accessible, has_parking. The committed venue vectors and stats are shipped verbatim from the pickle.

The engine filters to your city (falling back to the whole state if fewer than 2 venues match, then applies your optional budget cap at 1.2×), then ranks by cosine similarity. Travelers > 2 nudges toward aud_all (group/family) venues; 1–2 toward aud_adults.

Honest note: this is the real committed engine data (the pickle's exact venue feature matrix, feature columns and config), with the recommender reimplemented faithfully in vanilla JS. It reproduces the Python RecommendationAgent.recommend() ranking exactly on tested inputs — including the agent's own budget-tier mapping behavior — so what you see here matches what the full app's sub-agent returns.

About

An AI travel agent that generates personalized itineraries, cost estimates, and venue recommendations for US destinations. Built with FastAPI, a local Llama 3 model via Ollama, and scikit-learn cost models — coordinated as a multi-agent system.
