A live, in-browser slice of imgRetrieval — a local image-search engine that indexes the photos on your machine and finds them by example image, by text, or by both. The full system uses SIFT BoW/VLAD + CLIP and a FastAPI server; this demo runs the same retrieve → geometrically re-rank pipeline entirely client-side over 24 bundled public photos — including a real Harris-corner + RANSAC verifier. No setup, no upload, no server. How it maps to the real engine ↓ at the bottom.

How this demo maps to the real engine

This demo (in-browser)imgRetrieval (the real system)
Visual similarity — a color-grid + HOG-style gradient embedding, cosine ranked CLIP image embeddings & SIFT→VLAD (PCA-whitened) vectors, cosine
VLAD + RANSAC — real Harris corners + patch matches + RANSAC affine, re-ranked by inlier count SIFT keypoints + RANSAC homography (geomverify.py), identical re-rank rule
Text → image — TF-IDF cosine over the bundled captions CLIP shared text/image space and the same caption TF-IDF path (search.py)
Fusion — α-weighted blend of the text and image scores α-weighted blend of CLIP text + image embeddings, then cosine
The headline is the RANSAC re-rank: appearance search alone confuses similarly-coloured scenes, but geometric verification proves a true match by fitting a transform between the two images' keypoints. Search the cafe or library photo with VLAD + RANSAC — their rotated / cropped / scaled / brightened near-duplicates rise to the top with high inlier counts, exactly as in the real engine.

Photos: 24 freely-usable images from picsum.photos (Unsplash license) + synthesized geometric variants of two of them. No personal data anywhere — the same demo set the repo ships.
