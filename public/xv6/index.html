xv6 — kernel hacking

Coursework repo xv6_hw: a set of modifications to MIT's xv6 teaching operating system (a clean re-implementation of Unix v6 for x86). Each homework lives on its own branch and touches the real kernel — adding system calls, rewriting the CPU scheduler, and wiring a Unix-style signals layer. The headline assignment (HW05, mlq branch) replaces xv6's round-robin scheduler with a 3-level Multi-Level Queue scheduler; the live demo below runs that exact policy.

xv6 process model — the substrate every HW builds on

  • Each process is a struct proc in a fixed ptable.proc[NPROC] array, guarded by a single ptable.lock spinlock.
  • States cycle through UNUSED → EMBRYO → RUNNABLE ⇄ RUNNING ⇄ SLEEPING → ZOMBIE.
  • The per-CPU scheduler() loop picks a RUNNABLE proc and swtch()es into it; the process later yields control back via swtch(&c->scheduler, ...).
  • A syscall = add the handler to sysproc.c, register it in syscall.c, give it a number in syscall.h, and add a usys.S trap stub + a user.h prototype. The HWs do exactly this for lsproc, setpriority, signal…

HW05 — a 3-level Multi-Level Queue scheduler

The assignment replaces xv6's flat round-robin with a preemptive priority scheduler. The rules below are taken verbatim from the branch README and are exactly what the live demo enforces.

  • Three priority levels 2 (highest) … 0 (lowest). A new process starts at priority 1 (p->priority = 1 in allocproc).
  • On every timer tick the highest-priority RUNNABLE process runs — preemptive.
  • Within a level, processes run round-robin.
  • Per-level time slices (priority → ticks): (2 → 8), (1 → 16), (0 → 32) — stored in p->ctime.
  • A running process is not preempted by an equal-priority peer; it only stops when a higher-priority process becomes RUNNABLE, or when it relinquishes the CPU / finishes its slice.
  • If it yields early, its slice is reset (re-charged to the level's full value next time).
  • int set_priority(int new_priority) — new syscall, sets the caller's priority (0..2) and re-charges its slice.

How scheduler() was rewritten — proc.c

  • Scan ptable for the RUNNABLE proc with the maximum priority (high_prio_proc).
  • If its ctime (slice) is 0, recharge it to 8 / 16 / 32 based on its level.
  • swtch() into it; each tick decrement ctime and bump rticks (run ticks). Sleeping procs accrue IO_ticks; other RUNNABLE procs accrue wticks.
  • After each tick, re-scan: if any proc has strictly higher priority and is RUNNABLE, set check_value = 0 to preempt and break out.
  • Loop continues while ctime != 0 && state == RUNNABLE && !preempted.

procdump() (Ctrl-P) was also extended to print the new priority column for every process.

This runs the exact policy from the mlq branch: pick the highest-priority RUNNABLE process, run it round-robin within its level for up to its time slice (8/16/32 ticks), preempt the instant a higher-priority process becomes RUNNABLE. waitpid — wait for a specific child — testwait.c · proc.c

xv6's stock wait() reaps any child. The HW04 extension reaps a chosen pid and reports its accounting (wait / run / I-O ticks) — the checkRelinquished() routine in the scheduler branch frees the ZOMBIE's kernel stack & page table and returns its pid, mirroring waitpid(). testwait.c forks a child, then blocks on it specifically.

Unix-style signals (prepare-signal branch)

A from-scratch signals layer modelled on POSIX. The interface (signal.h) declares signal() to register a handler and sigsend() to deliver a signal to a pid, with the familiar SIG_DFL / SIG_IGN / SIG_ERR sentinels and numbers (SIGKILL 9, SIGSTOP 16, SIGCONT 17…).

The delivery mechanism — the hard part

  • Each struct proc gains a pending_signals bitset, a sighandler[NUMSIGNALS] table, an executing_signal flag, and a user_backup trap frame.
  • check_signals(tf) runs just before returning to user space (from trapasm.S). If a signal is pending and the CPU is at user privilege (DPL 3), it dispatches it.
  • To run a user-space handler it backs up the trap frame, pushes a tiny trampoline (invokesigret_start … invokesigret_end) onto the user stack, sets eip to the handler, and arranges that when the handler returns it lands in the trampoline which calls sigret.
  • sigret() restores the saved trap frame (memmove(p->tf, &p->user_backup, …)), resuming the interrupted user program as if nothing happened.

This branch is the scaffolded version (handler-selection / mask logic marked TODO), but the trap-frame backup/restore trampoline — the genuinely tricky kernel/user boundary crossing — is implemented.

The rewritten scheduler core — proc.c (mlq branch)

void scheduler(void){
  struct proc *p, *high_prio_proc;
  struct cpu *c = mycpu(); c->proc = 0;
  for(;;){
    sti(); acquire(&ptable.lock);
    for(high_prio_proc = ptable.proc; high_prio_proc < &ptable.proc[NPROC]; high_prio_proc++){
      if(high_prio_proc->state != RUNNABLE) continue;
      // find the RUNNABLE process with the highest priority
      for(p = ptable.proc; p < &ptable.proc[NPROC]; p++)
        if(high_prio_proc->priority < p->priority && p->state == RUNNABLE)
          high_prio_proc = p;

      int check_value = 1;                    // 0 ⇒ preempted
      if(high_prio_proc->ctime == 0){             // recharge time-slice for its level
        if(high_prio_proc->priority==2){high_prio_proc->ctime=8; break;}
        if(high_prio_proc->priority==1){high_prio_proc->ctime=16;break;}
        if(high_prio_proc->priority==0){high_prio_proc->ctime=32;break;}
      }
      while(high_prio_proc->ctime != 0 && high_prio_proc->state == RUNNABLE && check_value){
        c->proc = high_prio_proc;
        high_prio_proc->rticks++; high_prio_proc->ctime--;   // account 1 tick
        switchuvm(high_prio_proc); high_prio_proc->state = RUNNING;
        swtch(&(c->scheduler), high_prio_proc->context); switchkvm(); c->proc = 0;
        for(p = ptable.proc; p < &ptable.proc[NPROC]; p++){      // timing bookkeeping
          if(p->state == SLEEPING) p->IO_ticks++;
          if(high_prio_proc != p && p->state == RUNNABLE) p->wticks++;
        }
        for(p = ptable.proc; p < &ptable.proc[NPROC]; p++)     // preempt on higher prio
          if(p->priority > high_prio_proc->priority && p->state==RUNNABLE){ check_value = 0; break; }
      }
    }
    release(&ptable.lock);
  }
}

The setpriority syscall + lsproc — proc.c / sysproc.c

int setpriority(int prio){
  struct proc *curproc = myproc(); acquire(&ptable.lock);
  if(prio > 2 || prio < 0){ release(&ptable.lock); return 1; }
  if(prio==2){ curproc->priority=2; curproc->ctime=8;  }
  else if(prio==1){ curproc->priority=1; curproc->ctime=16; }
  else if(prio==0){ curproc->priority=0; curproc->ctime=32; }
  curproc->state = RUNNABLE; sched();          // yield: re-enter scheduler with new prio
  release(&ptable.lock); return 22;
}

// HW04 — list all live processes (sysproc.c wraps this as SYS_lsproc 22)
int lsproc(void){
  struct proc *p; sti(); acquire(&ptable.lock);
  cprintf("name\t\tpid\tstate\t\taddress\n\n");
  for(p = ptable.proc; p < &ptable.proc[NPROC]; p++){
    if(p->state == RUNNABLE) cprintf("%s\t\t%d\tRUNNABLE\t%p\n", p->name, p->pid, p->pgdir);
    else if(p->state == RUNNING)  cprintf("%s\t\t%d\tRUNNING\t\t%p\n", p->name, p->pid, p->pgdir);
    else if(p->state == SLEEPING) cprintf("%s\t\t%d\tSLEEPING\t%p\n", p->name, p->pid, p->pgdir);
  }
  release(&ptable.lock); return 22;
}
