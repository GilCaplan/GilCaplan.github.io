WhatsApp Persona Bot

A Go bot that impersonates a custom persona on WhatsApp using a local LLM (Ollama / llama3.2). It connects as your own WhatsApp account via the whatsmeow library, watches a target individual or group chat, and replies in character — with natural group behaviour (doesn't answer every message) and anti-jailbreak defenses.
Go 1.25 · whatsmeow Ollama / llama3.2 (local) SQLite session store Auth-bound · runs locally
This bot is auth-bound — it needs a QR-scanned WhatsApp session and a running Ollama instance, so it cannot run live in a browser. This page is a faithful explainer of the real code in bot.go and persona.go.

How it works

The whole bot is a single Go program (bot.go). On first run it shows a QR code in the terminal; you scan it with WhatsApp to authenticate. The encrypted session is saved to a local SQLite file (DB_PATH, default bot.db) so you only scan once. From then on, it listens to live message events and replies as the configured persona via a local LLM.

whatsmeow client
Connects to WhatsApp Web protocol as you. Receives events.Message and events.HistorySync; sends replies with a typing indicator.
Local LLM (Ollama)
Calls POST localhost:11434/api/chat with model llama3.2:latest. The persona is the system prompt; conversation history is the message list.
Two target modes
individual — one private contact (looked up by phone). group — a named/JID group chat, with selective participation.
Debounced replies
Waits ~9s after a message and resets on each new one (burst-batching), so it answers once per burst — like a human reading then replying. Burst caps at 25s.
Anti-jailbreak layer
Inbound text is scanned + filtered for injection patterns; detected attempts are silently ignored and never added to history.
Manual trigger
You can send 1 hey from your own phone; the bot treats "hey" as if the target said it and replies instantly (sandbox/testing).

How a persona is defined

A persona is a Go const IDENTITY string in bot.go (or persona.go) plus a matching PERSONA_NAME. It uses four sections — IDENTITY & BIO, PERSONA PROFILE, COMMUNICATION STYLE, GUIDELINES — and becomes the LLM's system prompt (concatenated with the universal anti-jailbreak rules). The blank template ships in persona.go:

const IDENTITY = ` # IDENTITY & BIO - Name: [FILL IN YOUR NAME HERE] - Role: [FILL IN YOUR ROLE HERE, e.g., Software Engineer, Researcher] - Background: [FILL IN YOUR BACKGROUND HERE] - Key Traits: [Reliable], [Motivated], [Loyal to family and friends], [Ambitious] # PERSONA PROFILE 1. [Fact 1] 2. [Fact 2] # COMMUNICATION STYLE - Tone: [Knowledgeable, supportive, slightly informal...] - Constraints: [Concise sentences. Avoid "As an AI..." phrases.] - Vocabulary: [Use technical terms appropriately but keep accessible.] # GUIDELINES - Stay in character at all times. - Prioritize the [Intention] in every response.`

The active persona in bot.go is "Leo" (a sharp-witted London interior architect). persona.go also ships several ready-made example personas. Switch them below to see the real config strings from the repo.

Group-chat participation logic

In group mode the bot behaves like a real participant — it does not reply to every message. Logic verbatim from handleIncomingMessage() + README:

SituationAction
Message contains the persona's name (e.g. "Leo")Always reply
Message @mentions someone else (not the bot)Skip
General messageAsk LLM (shouldRespond); else 40% random
You send 1 [message]Always reply, immediately
Message contains a link (http/www)Ignore

The "should I jump in?" check

shouldRespond() asks the LLM a yes/no question with a 10s timeout. On error or timeout it falls back to a random 40% chance:

prompt := fmt.Sprintf(`You are deciding whether %s would naturally jump into a group chat conversation. %s's persona: witty, social, opinionated — speaks up when there's something worth saying. Message: "%s" Would %s naturally respond to this? Reply with only YES or NO.`, PERSONA_NAME, PERSONA_NAME, text, PERSONA_NAME) // ... answer := strings.ToUpper(strings.TrimSpace(resp.Message.Content)) return strings.HasPrefix(answer, "YES")

In group mode, "them" messages are prefixed with the sender's WhatsApp push-name (Name: text) so the LLM knows who said what; a context note tells it not to echo those prefixes.

Anti-jailbreak & prompt-injection defense

Two layers protect the persona. (1) A fixed ANTI_JAILBREAK_RULES block is appended to every system prompt. (2) Inbound text passes through sanitizeUserInput() before it can reach the LLM or history.

  • detectPromptInjection() scans (lowercased) for ~45 patterns: system prompt, ignore previous, you are now, jailbreak, developer mode, act as, <script, base64, and more.
  • aggressiveFilterText() strips dangerous phrases, code fences, brackets [] <>, and excessive ### --- === formatting.
  • If injection is detected, the message is silently ignored — no reply, and it is not added to history ("complete silent treatment").
  • A failsafe character-break check on the LLM's reply: if it contains phrases like "as an AI", "as a language model", "i cannot pretend", it's discarded and replaced with an in-character fallback.
  • Messages containing links (http://, https://, www.) are ignored outright.

Configuration (.env)

Individual (private chat)

TARGET_TYPE=individual DB_PATH=bot.db TARGET_PHONE=15551234567

Group chat

TARGET_TYPE=group DB_PATH=bot.db TARGET_GROUP_NAME=My Group Chat # or, faster startup: # TARGET_GROUP_JID=123456789-987654321@g.us

Phone numbers in any format (spaces, dashes, +) are stripped by sanitizePhone(). Each instance needs its own DB file. .env and bot.db are gitignored — credentials never leave the machine.

Run it

git clone https://github.com/GilCaplan/whatsapp_chatbot.git cd whatsapp_chatbot go mod tidy ollama pull llama3.2:latest # local LLM cp .env.example .env # then edit TARGET_* go run bot.go # scan the QR on first run

Testing without the other person

Send a message from your own WhatsApp in the target chat prefixed with 1:

1 hey what's up?

The bot strips the 1 and treats "hey what's up?" as if the other person sent it, replying immediately (SANDBOX_TRIGGER = "1").
