What it does

Two user journeys, as described in the project’s APP_EXPLANATION.md / FEATURES_DESCRIPTION.md:

Content creation & management

Users build personal libraries of interview questions and full templates — manually, with an integrated AI assistant, or in live real‑time collaborative sessions with peers. A host‑led suggestion/approval queue keeps the final template curated.

Interview simulation & practice

Launch a mock interview from any template. Questions are presented sequentially with a progress bar; objective types (multiple‑choice, true/false) are auto‑graded.

Real‑time collaboration

Sessions with a unique 6‑char code, optional password, host controls, and view‑only / suggestions‑only permission modes — powered by Flask‑SocketIO (WebSockets).

AI co‑pilot

Google Gemini 1.5 Flash generates structured questions and per‑field suggestions. A mock generator is the automatic fallback when no API key is set or rate limits are hit.

Security‑first backend

Stateless JWT auth, PBKDF2‑SHA256 password hashing, request rate limiting, CORS, and input validation. Only the web container is client‑facing.

Context

Built as a Technion course project judged on backend robustness (the brief explicitly states no points for AI complexity or visual design). The requirements emphasize a multi‑image Docker setup, MongoDB persistence, never storing plain‑text passwords, spam protection, scalability, and a full test matrix — unit, integration, system, stress, and security tests.

Grounded in: README.md, documentation/APP_EXPLANATION.md, documentation/FEATURES_DESCRIPTION.md, documentation/INSTRUCTIONS.md.

Service topology

Three containers defined in docker-compose.yml (server, client, db: mongo:latest), plus the optional external Gemini API. The React client talks only to Flask; Flask talks to MongoDB and Gemini.

Real‑time collaborative sessions

The most developed feature. A host creates a session (unique 6‑char code, optional password), peers join, and questions move through a building queue → host review → finalized “ready” list.

Host controls & permissions

  • Manage participants (remove users)
  • Finalize questions; accept / reject suggestions
  • Configure view‑only or suggestions‑only modes

Suggestion & approval workflow

New questions and user suggestions land in a “building queue.” The host reviews, edits, and finalizes them into the “ready” list — ensuring curated, high‑quality content in the final template.

Grounded in: server/app/websocket_handlers.py, server/app/sessions.py, documentation/FEATURES_DESCRIPTION.md, and the React Session* components.
