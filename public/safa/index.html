The course in one page

Computational Psycholinguistics combines human language processing with computational linguistics — grammar formalisms, language models, and the cognitive theory of how people understand sentences in real time. The running theme of this repo is surprisal theory: words that are less probable in context take longer to read.

surprisal(wᵢ) = −log₂ P(wᵢ | w₁ … wᵢ₋₁)   ⟶   reading time

Linguistic-exposure estimation, n-gram tuning + reading-time/surprisal, logistic regression on the dative alternation, garden-path test suites, and a regex syllabifier + CFG parser. Two of these are live demos in this artifact.

"Surprisals & RT's" — Gil Caplan & Ido Beigelman. Compares a KenLM trigram and Pythia neural LM at predicting human reading times on the OneStop corpus, with spillover, GAMs, and an entropy study across model sizes.

Live · Regex syllabifier (HW5 · Pset_5_regex.ipynb)

HW5 asks for a syllabify(word) function that splits an English orthographic word — including made-up "nonce" words — into syllables using general phonotactic rules, not a dictionary. This is a faithful JS port of the notebook's algorithm. Type a word:

How the real algorithm works (ported verbatim)

  1. Find vowel nuclei. Scan left→right; a vowel (aeiouy) is a nucleus, and a recognized diphthong (ai, ea, ou, oy, …) counts as one nucleus spanning two letters.
  2. Place boundaries between nuclei. Look at the consonant cluster between each pair of vowels. Empty or single consonant → the consonant joins the following syllable (CV preference). Multiple consonants → onset maximization: give the next syllable the longest legal onset cluster (str, bl, th…) while avoiding illegal onsets (tl, nt, mb…).
  3. Post-process. Any syllable with no vowel is merged into its neighbour.
vowels = 'aeiouy'
diphthongs = ['ai','au','ay','ea','ee','ei','eu','ey','ie','oa','oi','oo','ou','oy','ue','ui','aw','ew','ow']
legal_onsets = {'bl','br','cl','cr','dr','fl','fr','gl','gr','pl','pr','tr','tw',
                'sc','sk','sl','sm','sn','sp','st','sw','sh','th','wh','ch','qu',
                'scr','spl','spr','str','squ','thr','shr','chr', ...single consonants}
# multi-consonant cluster → try longest legal onset for the next syllable
for onset_len in range(min(3,len(cluster)), 0, -1):
    if cluster[-onset_len:] in legal_onsets: split_point = v2_start - onset_len; break
The notebook scores this on test sets — clean CV words like capable→ca·pa·ble and nonce words like snoded→sno·ded work; the honest weak spots it documents are compounds (playground), silent letters (castle, island) and morphology, where pure phonotactics over-splits.

Live · CFG parser (HW5 · Copy_of_Pset_5_cfg.ipynb)

HW5's CFG task builds context-free grammars in NLTK and parses sentences with a bottom-up chart parser. The final grammar handles filler–gap dependencies (wh-questions and embedded clauses) using "slash" categories (S_SLASH_NP — a clause missing a noun phrase). Below is that exact grammar ported to a JS chart parser. Pick a sentence — accepted sentences should parse, the bad ones should be rejected:

The grammar (filler–gap / slash-categories, from the notebook)

S        -> NP VP
NP       -> Det N | Pronoun
VP       -> V_INTRANS | V_TRANS NP | V_SBAR SBAR
SBAR     -> WHNP S | WHNP S_SLASH_NP | COMP S
S_SLASH_NP   -> VP_SLASH_NP | NP VP_SLASH_NP
VP_SLASH_NP  -> V_INTRANS | V_TRANS | V_TRANS NP
             |  V_SBAR SBAR | V_SBAR SBAR_SLASH_NP
SBAR_SLASH_NP-> WHNP S_SLASH_NP | S_SLASH_NP
COMP -> 'that' | ε     WHNP -> 'who' | 'what'
Det -> the|a|an|my|your|her|his|their     N -> joke|women|street|apple
Pronoun -> I|you|she|he|they
V_INTRANS -> 'slept'   V_TRANS -> 'devoured'   V_SBAR -> 'know'|'said'

The slash category S_SLASH_NP = "a sentence with a noun-phrase gap somewhere inside it". It lets "you know what I devoured ___" parse — the wh-word what is the filler and the gap is the missing object of devoured — while rejecting "I slept that you said" (an intransitive verb cannot take a clause).

Implemented here as a CKY-style chart parser over the grammar above (ε-productions and unit rules expanded). The notebook uses NLTK's BottomUpChartParser and checks each good_sentence parses and each bad_sentence is rejected.

Live · Surprisal, the central quantity

Every word gets a surprisal = how unexpected it is given the previous words. Higher bars = more surprising = (predicted) slower reading. Pick a sentence; bar heights come from a small in-page n-gram — the same quantity task_1.py gets from KenLM.

Bar height ∝ surprisal in bits = −log₂ P(word | context), computed live from a small in-page bigram back-off language model. Words the model has seen following the previous word are low-surprisal; unseen / rare continuations back off to the unigram and score high.

Surprisal → reading time (illustrative scatter)

The project's core claim is that higher surprisal → longer reading time, a roughly linear trend. Here a fixed mini-corpus of sentences is scored word-by-word; each dot is a word (its in-page surprisal vs a synthetic RT = baseline + slope·surprisal + noise). The fitted line and R² mirror the shape of the real linregress in task_1.py — clearly illustrative, not the trained model.

Task 2 · Non-linear GAM modelling (safa_project_part2.ipynb)

Relaxes the straight-line assumption with Generalized Additive Models (pygam), fitting smooth splines of RT on current + lag-1 (spillover) surprisal while controlling for word length and log-frequency, across three reading-time measures.

from pygam import LinearGAM, s
rt_measures = ['IA_DWELL_TIME','IA_FIRST_RUN_DWELL_TIME','IA_REGRESSION_PATH_DURATION']
df['surprisal_spill'] = df.groupby([...])['pythia_surprisal'].shift(1)  # lag-1 spillover
gam = LinearGAM(s(0)+s(1)+s(2)+s(3)).gridsearch(X, y)   # surprisal, spillover, length, freq

Finding: RT rises with both current and spillover surprisal across all three measures, but the current-word effect is markedly larger, and for first-run / regression-path duration the spillover effect attenuates at high surprisal (diminishing returns).

Project · Beyond surprisal — entropy & model scaling (unstructered/ido_main.py, utils.py)

The open-ended part asks: does the model's uncertainty about the upcoming word (next-word entropy) predict reading difficulty beyond the unexpectedness of the current word (surprisal)? And how does this change as the model grows from 70M to 1.4B parameters?

H(i) = −Σ_w p(w) · log₂ p(w)   (next-word entropy at position i)

compute_word_stats() in utils.py computes both per-word surprisal and entropy from Pythia's softmax; test_hypotheses_() fits three nested linear models (surprisal-only, entropy-only, combined) and reports R² with an OLS F-test. Run across five Pythia sizes in ido_main.py.

Result figures (the repo's own PNGs)

Entropy analysis (unstructered/entropy_analysis_results.png): R² of surprisal-only, entropy-only and combined models, and how they scale with model size.

H1Surprisal vs entropy as a predictorSurprisal wins: R²=0.0749 vs 0.0538 (≈39% better)

Headline finding: next-word entropy carries predictive power beyond current-word surprisal — uncertainty about what's coming, not just surprise at what arrived, contributes to reading effort. And a striking scaling result: psycholinguistic validity decreases as the model grows (surprisal R² drops 0.0749→0.0570, a 24% reduction from 70M→1.4B) — bigger models fit human reading worse, consistent with Oh & Schuler (2023). Source: safa_project (2).pdf.
