📅 MACalendar
desktop app · showcase
A privacy-focused, voice-driven calendar & task assistant for macOS (PyQt6 desktop app). Speech-to-text runs locally with faster-whisper; reasoning defaults to a local Ollama model (or OpenAI / Gemini / Claude if you opt in). Press a hotkey, speak a request, and it parses your intent and updates a local SQLite calendar — no audio leaves your Mac by default. Everything below is grounded in the repo's README, config.example.yaml, and source.

From your voice to a calendar change

Click a stage. The orchestration is in assistant/pipeline.py (Pipeline._run_pipeline): AudioCapture → STT → IntentParser → ConfirmationHandler → Action.execute(), running on a worker thread that streams status to the PyQt6 UI.

Select a stage above.

⚡ Rule fast-path (no LLM)

A spaCy-based RuleBasedParser tries first. If its confidence ≥ threshold with no missing slots, the command executes immediately — no model call. Simple, single-event commands (e.g. "meeting tomorrow at 10am") take this path.

🤖 Background verify

After a fast-path action runs, a daemon thread can ask the LLM to judge it in three tiers: ok (silent), minor (silently PATCH fields), major (undo the create, re-execute the corrected intent) — but only if the user hasn't already edited the record.

Stop words: say "execute", "done", "stop", "set events" (and more) to finish recording immediately. A streaming transcription checks the growing audio buffer every 2.5s to detect them. Source: _BUILTIN_STOP_PATTERNS in pipeline.py.

What it does

iPhone companion (SwiftUI + Flask API)

The Mac is the source of truth; a native SwiftUI app connects over Tailscale to a Flask REST API (python -m assistant.api --tailscale). Quick reference (README):

GET/events?date=YYYY-MM-DDEvents for a day

GET/todosTodo list

Tasks-mode voice commands

When the Tasks tab is active the mic enters Tasks mode — the transcript is prefixed [TASKS VIEW] so the parser biases toward todo actions. Phrases from README; actions from actions/todo/action.py.

"Add task buy groceries"
"Add tasks: buy milk, call dentist, walk the dog" → multiple
"Mark buy milk done" · "Rename buy milk to buy oat milk"

config.example.yaml (verbatim)

hotkey:
  modifiers: ["cmd", "shift"]
  key: "space"

# whisper = free, local, no internet
stt_engine: "whisper"
whisper:
  model_size: "base"     # tiny|base|small|medium|large-v3
  compute_type: "int8"   # fastest on Apple Silicon
  device: "cpu"
  language: "en"

# ollama (default) | openai | gemini | claude
llm_engine: "ollama"
ollama:
  base_url: "http://localhost:11434"
  model: "llama3.1:8b"
  temperature: 0.1
  timeout_seconds: 180

# 0 = fully autonomous, 1 = yes/no per action
confirmation_level: 1

tts:
  mute: false
  voice: "Samantha"   # say -v ? to list
  rate: 200

Install & run (from README)

Prerequisites

macOS · Python 3.11+ · microphone permission · Ollama with ollama pull llama3.1:8b.

Install

python3.11 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -e .

cp config.example.yaml config.yaml

Run

# Easy way: double-click in Finder
Launch Calendar.command

# Terminal way
python -m assistant.main

Test

python tests/test_ollama_parser.py   # needs Ollama
python tests/test_todo_parser.py --direct  # no LLM
pytest tests/

Privacy

By default everything is local: audio is transcribed on-device with faster-whisper and reasoning runs through local Ollama. Switching llm_engine to openai, gemini, or claude sends transcripts to that provider. Basic prompt-injection sanitization guards against malicious voice commands. State persists to a local .db file on close.
