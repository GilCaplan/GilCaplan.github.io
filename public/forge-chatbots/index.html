ChatbotForge
interactive explainer · showcase
Answer a few wizard questions and ChatbotForge writes a complete, runnable chatbot codebase — a FastAPI backend with SSE streaming, a web chat UI, a terminal client, and an optional ChromaDB RAG pipeline. Generation is template-driven: a ChatbotConfig feeds a Jinja2 renderer, and a file manifest decides exactly which template files to emit. Everything below is taken from the real repo (schema, manifest, templates, README).

Any saved config can be replayed (--config bot.json) or re-opened for editing (--edit ./output/movie_recommender). The model name is filled from DEFAULT_MODELS when left blank.

Run the generated chatbot (from README)

cd output/movie_recommender
cp .env.example .env        # skip for Ollama; set OPENAI_API_KEY etc. otherwise
python run.py               # web UI at http://localhost:8000
python client.py            # terminal client (second terminal)
python ingest/ingest.py     # build the ChromaDB index first (RAG projects only)

API of the generated chatbot

Endpoints emitted by the backend routers (routers/chat.py, health.py, manage.py). Verbatim from README.

EndpointMethodDescription
/api/chatPOSTSend message, returns an SSE token stream
/api/chatsGETList all chat sessions
/api/chats/{id}/historyGETFull message history
/api/chats/{id}DELETEDelete a chat session
/api/manage/sourcesGETList RAG data sources (RAG only)
/api/manage/add-sourcePOSTAdd a data source (RAG only)
/api/manage/reindexPOSTRe-run ingestion & reload vector store (RAG only)
/healthGETHealth check

SSE events from /api/chat

{"text": "chunk of text", "chat_id": "uuid"}   // token chunk
{"done": true, "chat_id": "uuid"}               // stream complete
{"error": "message"}                            // on failure

RAG responses cite verified sources as [Source N]; citations are streamed as an extra event before done (chat.py template).
