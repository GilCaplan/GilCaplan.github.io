What's in this repository

Three self-contained assignments from the NLP course, each grounded in real code and data in the repo.

HW1 — POS tagging (MEMM + Viterbi)

A part-of-speech tagger trained on train1.wtag / train2.wtag, decoded with the Viterbi algorithm over hand-built feature templates. Predictions are written for comp1.words / comp2.words.

HW2 — BPE tokenizer + NER

A from-scratch Byte-Pair-Encoding tokenizer extending a BaseTokenizer, trained on domain text, then evaluated on a binary NER task using "first-subtoken" labeling. Three trained tokenizers are shipped as .pkl.

Final project — LLM reasoning eval

A 270-example benchmark of timezone / flight-duration reasoning questions. Four Gemini models are scored with a mathematical validator (no string matching), revealing a striking weakness on multi-step arithmetic reasoning.

The data format (real lines)

Training data is whitespace-separated word_TAG tokens, one sentence per line. Inputs to tag (comp1.words) are raw words. The model estimates P(tag | word, context) via a log-linear feature model and decodes the most-likely sequence with Viterbi, with explicit handling of unknown words.

The README frames HW1 as "Hidden Markov Models for POS tagging using the Viterbi algorithm" with transition/emission estimation and unknown-word handling. The shipped code (optimization.py) trains feature weights that Viterbi then decodes.

What is measured

Per the assignment README, tokenizers are compared on:

  • Correctness — does it implement BPE faithfully (encode/decode round-trip)?
  • Speed — tokens encoded per second.
  • Efficiency — tokens needed to cover unseen text.
  • NER performance — binary entity / non-entity F1 on the downstream task.
NER uses first-subtoken labeling: when a word splits into subwords, only the first subtoken carries the entity label; remaining subtokens are set to -100 (ignored in the loss). Example from the README: "Steve Jobs" → ["Steve J", "ob", "s ate"], only "Steve J" gets label 1.

How a response is scored (the real criterion)

Scoring is mathematical, not string-matching. A model's airport pair is valid iff the implied flight duration matches the stated duration within tolerance, after converting both endpoints to UTC:

Valid  ⟺  | duration_calc − duration_expected | ≤ tolerance
duration_calc = (t_arr − tz_dest) − (t_dep − tz_orig)   # in UTC minutes

Final score = macro-averaged accuracy: each question contributes equally, Acc = (1/n)·Σ xᵢ/r.

Results — real saved figures

Key findings (as the repo states them)

  • Four models tested: Gemini 1.5 Flash, 1.5 Flash-8B, 2.0 Flash, 2.5 Flash.
  • Overall accuracy is low (<10% macro-averaged) — the task isolates genuine multi-step arithmetic reasoning rather than recall.
  • Within-run consistency report: 960 questions, 85.05% consistency rate — answers are stable but frequently incorrect.
  • Reproducible with RANDOM_SEED=43 deterministic generation.
