A from-scratch generic 2-3 tree in Java, augmented with subtree sizes for order statistics, used to track race-runners by ID, minimum time and average time — plus theory homework.

The graded programming mini-project (src/) builds, in the README's words, "a dynamic 2-3 tree for runners." A 2-3 tree is a perfectly height-balanced search tree where every internal node has 2 or 3 children and all leaves sit at the same depth, giving O(log n) search / insert / delete.

Gil's implementation goes further: each node also stores the size of its subtree, so the tree supports order statistics — a Rank(x) query in O(log n). The Race class keeps three such trees in sync so it can answer "who is the fastest runner" and "what is runner X's rank" instantly.

Insert & split — the real code

Insert walks to the correct leaf's parent, calls Insert_And_Split, and propagates a new node z upward whenever a node overflowed to 4 children. If the root itself splits, a new root is created.

public void Insert(node<T> z) {
    z.setSize(1);
    node<T> y = this.root;
    while(!(y instanceof leaf)) {       // descend to leaf level
        if (checkSmaller(z, y.getLeft()))   y = y.getLeft();
        else if(checkSmaller(z, y.getMiddle())) y = y.getMiddle();
        else y = y.getRight();
    }
    internalNode<T> x = (internalNode<T>) y.getp();
    z = Insert_And_Split(x, z);            // may return overflow node
    while(x != this.root){
        x = (internalNode<T>) x.getp();
        if(z != null) z = Insert_And_Split(x, z);
        else Update_Key(x);
        UpdateSize(x);                     // maintain subtree sizes
    }
    if(z != null){                         // root split → grow height
        internalNode<T> w = new internalNode<>(null);
        Set_Children(w, x, z, null);
        this.root = w;  UpdateSize(root);
    }
}

Order statistics — Rank

Because every node caches its subtree size, the rank of a key is computed by summing the sizes of all subtrees that lie to its left on the path to the root — in O(log n).

public int Rank(node<T> x){
    int rank = 1;
    internalNode<T> y = (internalNode<T>) x.getp();
    while(y != null){
        if(x == y.getMiddle()) rank += y.getLeft().getSize();
        else if(x == y.getRight())
            rank += y.getLeft().getSize() + y.getMiddle().getSize();
        x = y;  y = (internalNode<T>) y.getp();
    }
    return rank;
}
Minimum() is just "go left until the leaf level, take the first non-sentinel leaf", giving the fastest runner in O(log n); the result is cached so getFastestRunnerMin() is O(1).

Keeping the trees consistent — fixMinAvgRuns

When a runner records a new time, its min/avg change, so its keys in the min/avg trees must move. The repo deletes the stale entry (using the cached previous value) and re-inserts the fresh one:

public void fixMinAvgRuns(RunnerID id, RunnerTree<RunnerID> runner) {
    minTree.Delete(new internalNode<>(id, runner.getPrevMinTime()));
    runner.setPrevMinTime(runner.getMinTime());
    avgTree.Delete(new internalNode<>(id, runner.getPrevAvgTime()));
    runner.setPrevAvgTime(runner.getAvgRun());
    minTree.Insert(new minRunner(runner));
    avgTree.Insert(new avgRunner(runner));
    fastedRunnerAvg = avgTree.Minimum().getKey();
    fastedRunnerMin = minTree.Minimum().getKey();
}

The min/avg trees are keyed by a secondary key (the float time) with the runner id as tie-breaker — see checkSmaller in twothreeTree.java, which compares getSecondaryKey() first and falls back to the id only on a tie.
